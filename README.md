## 📈 기능 요구사항

### 초간단 자동차 경주 게임을 구현한다.

- 주어진 횟수 동안 n대의 자동차는 전진 또는 멈출 수 있다.

- 각 자동차에 이름을 부여할 수 있다.

  전진하는 자동차를 출력할 때 자동차 이름을 같이 출력한다

- 자동차 이름은 쉼표(,)를 기준으로 구분하여 이름은 5자 이하만 가능하다.

- 사용자는 몇 번의 이동을 할 것인지 입력할 수 있어야 한다.

- 전진하는 조건은 0에서 9사이에서 무작위 값을 구한 후 무작위 값이 4 이상일 경우이다.

- 자동차 경주 게임을 완료한 후 누가 우승했는지를 알려준다. 우승자는 한 명 이상일 수 있다.

- 우승자가 여러 명일 경우 쉼표(,)를 이용하여 구분한다.

- 사용자가 잘못된 값을 입력할 경우 "[ERROR]"로 시작하는 메시지와 함께 Error를 발생시킨 후 애플리케이션은 종료되어야 한다.

## 💻 프로그래밍 요구사항

  - 단일 책임 원칙(SRP) 준수

  - 각 기능별 단위 테스트 적용

## 🤔 스스로 판단한 예외 처리

- 에러는 `[ERROR]`로 시작하는 에러 메시지를 출력 후 애플리케이션은 종료되어야 한다.
- 별도의 객체 형식의 에러 상수 파일을 만들어 사용

### 자동차 이름 입력 관련 에러

- **자동차 이름을 입력 안했을 경우**

  - ex) `'' or '  '`
  - 이 경우는 띄어쓰기도 입력 안한걸로 간주
  - `[ERROR] 경주할 자동차 이름을 입력해주세요.`

- **자동차 이름이 5글자를 초과한 경우**

  - ex) `pobi, kimsuro`
  - `[ERROR] 자동차의 이름은 1자 이상 5자 이하로 입력 해야 합니다.`

### 시도할 횟수 입력 관련 에러

- **숫자 형식이 아닌 경우**

  - ex) `a`, `1a`, `abc`
  - `[ERROR] 시도 횟수는 숫자 형식이어야 합니다.`

- **숫자가 소수인 경우**

  - ex) `1.5`
  - `[ERROR] 시도 횟수는 양의 정수만 입력 가능합니다.`

- **시도 횟수가 0 이하이거나 MAX_SAFE_INTEGER를 넘을 경우**
  - ex) `0`, `-1`, `9007199254740992`
  - `MAX_SAFE_INTEGER` : 9,007,199,254,740,991
  - `[ERROR] 시도 횟수는 1부터 ${Number.MAX_SAFE_INTEGER} 까지의 수를 입력해야 합니다.`

## 🔁 기능 구현 리스트 순서

- `@woowacourse/mission-utils에서 제공하는 Random 및 Console API를 사용하여 구현해야 한다`
  - Random 값 추출은 Random.pickNumberInRange()를 활용
  - 사용자의 값을 입력 및 출력 하려면  
    `Console.readLineAsync()`와 `Console.print()`를 활용한다.

### 1. 각 자동차의 이름을 입력 받음

- 경주할 자동차 이름(쉼표 기준으로 구분)을 입력 받는다.

  - `경주할 자동차 이름을 입력하세요.(이름은 쉼표(,) 기준으로 구분)` 라는 문구가 나와야 함

### 2. 자동차의 이름을 정규화된 배열로 변환

- **쉼표를 기준으로 분리 후 각 이름의 앞뒤 공백 제거**

  - ex) `pobi, woni` → `["pobi", "woni"]`
  - ex) `pobi,  woni  , jun` → `["pobi", "woni", "jun"]`

- **연속된 쉼표나 빈 값은 무시**
  - ex) `pobi,,woni` → `["pobi", "woni"]`
  - ex) `pobi, , woni` → `["pobi", "woni"]`
  - ex) `,pobi,woni,` → `["pobi", "woni"]`

### 3. 입력 받은 자동차의 이름을 검증

```
- 자동차 이름을 입력 안했을 경우 ERROR를 throw
  - "[ERROR] 경주할 자동차 이름을 입력해주세요."

- 자동차 이름이 5글자를 초과한 경우 ERROR를 throw
  - "[ERROR] 자동차의 이름은 1자 이상 5자 이하로 입력 해야 합니다."
```

### 4. 시도할 횟수를 입력 받음

- 자동차 경주를 실행할 횟수를 입력 받는다
  - `시도할 횟수는 몇 회인가요?` 라는 문구가 나와야함

### 5. 시도할 횟수를 검증

```
- 숫자 형식이 아닌 경우 ERROR를 throw
  - "[ERROR] 시도 횟수는 숫자 형식이어야 합니다."

- 숫자가 소수인 경우 ERROR를 throw
  - "[ERROR] 시도 횟수는 양의 정수만 입력 가능합니다."

- 시도 횟수가 0 이하이거나 MAX_SAFE_INTEGER를 넘을 경우 ERROR를 throw
  - "[ERROR] 시도 횟수는 1부터 ${Number.MAX_SAFE_INTEGER} 까지의 수를 입력해야 합니다."
```

### 6. 횟수만큼 자동차 전진 여부를 계산 후 전진

```
- Random.pickNumberInRange(0, 9)를 사용하여 0 ~ 9 무작위 값 추출
  - 무작위 값이 4 이상일 경우 자동차를 1칸 전진
```

### 7. 횟수만큼 반복하여 결과를 출력

- 출력하기 전 `실행결과` 라는 문구가 한 번만 나와야함
- ex) 자동차 이름 : `pobi,woni,jun` 횟수 : `5`

```

실행 결과
pobi : -
woni :
jun : -

pobi : --
woni : -
jun : --

pobi : ---
woni : --
jun : ---

pobi : ----
woni : ---
jun : ----

pobi : -----
woni : ----
jun : -----
```

### 8. 우승자를 출력

- 우승자는 공동이 있을 수 있으며 있을경우 쉼표(,)로 구분한다.

  - 단독 우승자 안내 문구

  ```
  최종 우승자 : pobi
  ```

  - 공동 우승자 안내 문구

  ```
  최종 우승자 : pobi, jun
  ```

## 🔥 이번 2주차에서 지켜야 할 핵심

- **1. 요구 사항을 정확하게 준수**

- **2. 좋은 git 커밋 메시지를 작성**

- **3. 이름을 통해 의도를 드러내기**

  - 변수 이름, 함수(메서드) 이름, 클래스 이름을 신중하게 짓기
  - 연속된 숫자를 덧붙이거나(`a1,a2 ...`)
    불용어(`info, Data, a`)를 추가하는 방식은 적절하지 못함

- **4. 축약하지 않기**

  - 의도를 드러낼 수 있다면 이름이 길어져도 괜찮음
  - 클래스와 메서드 이름을 한 두단어로 유지하려고 노력하고 문맥을 중복하는 이름을 자제
    - ex) 클래스 이름이 Order이면 메서드 이름은 shipOrder라고 메서드 이름을 지을 필요 없이 짧게 ship으로 지으면 호출시 `Order.ship()`로 간단한 호출의 표현이 됨

- **5. 공백 라인을 의미 있게 사용**

  - 공백도 코딩 컨벤션이다

- **6. 의미 없는 주석을 달지 않기**

  - 이름을 통해 의도를 드러내고 힘든 경우만 주석을 달기
